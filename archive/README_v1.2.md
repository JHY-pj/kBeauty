# K-뷰티 데이터 전처리 프로그램

이 프로젝트는 GitHub 저장소 [`JHY-pj/kBeauty`](https://github.com/JHY-pj/kBeauty)의 `data/` 폴더에 있는 **Sephora 상품·리뷰 CSV**를 정리합니다. 실제 모델을 학습하기 전에 **오류가 있는 행을 분리하고, 리뷰 본문의 손상과 중복을 확인하고, 모델에 사용할 입력 파일을 만드는 코드**입니다.

기준으로 삼은 문서는 아래 두 개입니다.

- **03. Kaggle Sephora 상품·리뷰 데이터 품질 진단 및 모델링 가능성 평가 통합 보고서** — 데이터 구조·결측·중복·인코딩 문제를 확인한 보고서(2026-10-22)
- **04. 모델링 목적 및 평가 기준 정의서 v1.0** — 모델별 목적과 평가 원칙을 정의한 문서(2026-10-22)

> **검증 상태:** 가상 CSV를 사용한 자동 테스트는 통과했습니다. 실제 GitHub CSV 18개 약 532.5MB에 대한 **전체 전처리 실행은 아직 확인하지 않았습니다.** 아래 실행 절차로 전체 데이터를 검증해야 합니다.

## 1. 필요한 환경

- Python **3.10 이상**
- 별도 설치 패키지 없음(Python 기본 제공 기능만 사용)
- 원본 데이터가 있는 `data/` 폴더

이 압축파일의 다음 파일을 GitHub 프로젝트 최상위 폴더에 복사합니다.

```text
kBeauty/
├── data/                    # 기존 원본 CSV 저장 위치(수정하지 않음)
├── preprocess.py            # 데이터 전처리 실행 코드
├── README.md                # 지금 읽고 있는 한국어 안내서
├── VERIFICATION_REPORT.md   # 변경 내역과 테스트 결과
├── tests/
│   └── test_preprocess.py   # 가상 데이터 자동 테스트
└── .gitignore               # 전처리 결과·임시 파일의 Git 등록 제외 규칙
```

## 2. 실행 방법

Windows PowerShell:

```powershell
git clone https://github.com/JHY-pj/kBeauty.git
cd kBeauty

# 압축파일의 preprocess.py와 tests 폴더 등을 이 위치에 복사합니다.
python .\preprocess.py --data-dir .\data --out-dir .\outputs\preprocessed
```

macOS 또는 Linux:

```bash
git clone https://github.com/JHY-pj/kBeauty.git
cd kBeauty

# 압축파일의 preprocess.py와 tests 폴더 등을 이 위치에 복사합니다.
python3 preprocess.py --data-dir ./data --out-dir ./outputs/preprocessed
```

전처리 실행 중 원본 CSV는 **읽기만** 합니다. 결과 파일은 `outputs/preprocessed/`에 저장합니다.

### 선택 옵션

| 옵션 | 의미 |
|---|---|
| `--data-dir` | 원본 CSV가 있는 폴더를 지정합니다. 기본값은 `data`입니다. |
| `--out-dir` | 결과 파일이 저장될 폴더를 지정합니다. 기본값은 `outputs/preprocessed`입니다. |
| `--min-review-chars 20` | 모델 입력에 사용할 리뷰 본문 최소 글자 수입니다. 기본값은 20자입니다. 짧은 리뷰도 전체 정제본에는 남습니다. |
| `--hash-inputs` | 입력 파일별 SHA-256 해시를 계산해 실행 기록에 남깁니다. 약 533MB 전체를 추가로 읽으므로 시간이 더 걸릴 수 있습니다. |

실행 예시:

```powershell
python .\preprocess.py --data-dir .\data --out-dir .\outputs\preprocessed --hash-inputs
```

## 3. 생성 파일 안내

| 생성 파일 | 한국어 설명 |
|---|---|

| `products_quarantine.csv` | **검토가 필요한 상품 행.** 상품 ID가 잘못됐거나 같은 ID가 중복된 행을 따로 보관합니다. |
| `reviews_clean.csv` | **정제된 리뷰 전체 기록.** 유효한 행의 복원 여부·중복 여부·기간 분할 상태를 보존합니다. 학습 가능 행만 들어 있는 파일은 아닙니다. |
| `reviews_quarantine.csv` | **검토가 필요한 리뷰 행.** 상품 ID·평점·날짜·열 구조 등이 잘못된 행의 원래 값을 따로 보관합니다. |
| `reviews_m4_input.csv` | **M4 소비자 니즈·불만 분석용 리뷰 후보.** 효능·자극·향·질감 등의 정답값은 임의 생성하지 않습니다. |
| `reviews_m5_input.csv` | **M5 추천 여부 분석용 리뷰 후보.** 2018년 이후 추천 여부 값이 있는 행을 사용하며, 모델 입력에서 별점은 제외합니다. |
| `quality_report.json` | **전처리 결과 요약.** 파일 목록·건수·격리 사유·중복·분할 결과와 기존 품질 보고서 대비 차이를 저장합니다. |

> `products_clean.csv`에는 여러 뷰티 제품군의 상품 정보가 포함될 수 있습니다. 반면 현재 제공된 리뷰 원문 CSV는 스킨케어에 집중되어 있습니다. **다른 제품군에 실제 소비자 리뷰가 존재하지 않는다는 뜻이 아닙니다.**

## 4. 전처리 진행 순서

1. **상품 정보 읽기:** `product_info.csv`의 헤더와 상품 ID를 확인합니다. 잘못된 상품 ID나 중복 ID는 별도 파일에 기록합니다.
2. **상품 단위 정리:** 가격 숫자형 변환, 카테고리 경로 구성, 단일 용량 제품의 mL 환산 및 단위가격 계산을 수행합니다. g 단위를 mL로 억지 환산하지 않습니다.
3. **리뷰 파일 읽기:** 폴더의 `reviews_*.csv` 전체를 파일명 순서에 맞게 읽습니다. 실제 헤더 이름을 기준으로 열을 해석합니다.
4. **손상·오류 점검:** 구조가 맞지 않는 리뷰를 격리합니다. 알려진 텍스트 손상 패턴은 복원하되, 복원 여부와 남은 손상을 기록합니다.
5. **중복 식별:** 작성자와 정규화된 리뷰 본문으로 동일 작성자·동일 문장 중복을 파악합니다.
6. **시기별 분할:** 2021년까지 학습용, 2022년 검증용, 2023년 이후 시험용으로 나눕니다. 작성자 또는 동일 문장이 앞선 기간에 등장했다면 뒷기간 모델 입력에서는 제외해 데이터 누출을 줄입니다.
7. **모델용 후보 저장:** 최소 글자 수·리뷰 본문 손상 여부·기간/중복 조건을 통과한 행을 M4/M5 입력 파일에 저장합니다.
8. **처리 결과 기록:** `quality_report.json`에 처리 건수와 제외 사유를 남깁니다.

## 5. 품질 보고서에서 발견된 문제에 대한 처리

| 품질 보고서 항목 | 현재 프로그램의 처리 |
|---|---|
| D1. 인코딩 손상 | 알려진 손상 문장부호를 규칙에 따라 복원합니다. **리뷰 본문 손상과 제목·브랜드 등 부가정보 손상은 구분**합니다. 복원 정확도는 원문 표본 검토가 필요합니다. |
| D2. 동일 리뷰 복제 | 작성자·리뷰 문장 중복 여부를 기록하고, 모델 입력에서 동일 작성자·동일 문장 복제본을 제외합니다. 전체 정제본에는 보존합니다. |
| D3. 리뷰 데이터 범위 | 실제 제공된 리뷰 파일에서만 리뷰 기반 모델 입력을 만듭니다. 상품 전체 목록과 구분합니다. |
| D4. 데이터 시점 | 내부 학습·검증·시험 기간을 구분합니다. **2026년 최신 자료 외부 검증은 별도 단계**입니다. |
| D5. 추천 여부 결측 | M5는 2018년 이후 추천 여부 값이 있는 리뷰만 사용합니다. |
| D6. CSV 구조 오류 | 잘못된 상품 ID, 날짜, 평점, 필드 위치 등을 점검하고 오류 행을 별도 보관합니다. |
| D7. 긍정 리뷰 편중 | 전처리 단계에서 점수를 임의 조정하지 않습니다. 불균형 대응과 평가는 실제 모델링 단계에서 수행합니다. |
| D8. 작성자·상품 편향 | 앞선 시기에 등장한 작성자가 뒷기간에 다시 나오면 해당 뒷기간 데이터를 학습·평가 후보에서 제외합니다. |
| D9. 숫자 표기 차이 | 추천 여부의 `0/1`, `0.0/1.0` 형식을 통일하고 숫자·날짜를 변환합니다. |
| D10. 상품 속성 결측 | 없는 상품 속성을 추정해 채우지 않고 비워 둡니다. |
| D11. 협찬·보상성 리뷰 | 근거 없이 자동 제거하지 않습니다. 후속 모델 평가에서 제외 전후를 비교해야 합니다. |

## 6. 반드시 알아둘 한계

- **실제 전체 데이터 검증은 미완료:** 기존 03번 보고서는 리뷰 파일 19개, 현재 GitHub에는 리뷰 파일 17개입니다. 두 구간이 합쳐졌을 가능성이 있지만, 파일의 행 수와 내용이 일치하는지는 직접 실행해 확인해야 합니다.
- **과거 품질 보고서 참고값:** 읽은 리뷰 **1,092,530행**, 구조 정상 리뷰 **1,089,073행**. `quality_report.json`의 결과와 대조하세요. 차이가 있더라도 즉시 오류라고 단정하지 말고 파일 분할·파싱 방식·겹친 행을 점검해야 합니다.
- **손상 원문의 한계:** 이미 잘못 합쳐졌거나 사라진 CSV 행은 이 프로그램만으로 자동 복원되지 않습니다. 문장부호 복원도 원문 확인이 필요한 추정 처리입니다.
- **기간·중복 제외의 영향:** 누출 위험을 낮추기 위해 보수적으로 제외하므로 검증·시험 데이터가 줄어들 수 있습니다. 실제 학습 전 제외 건수·분포를 확인해야 합니다.
- **모델 범위의 한계:** 이 프로그램은 전처리 코드입니다. M0~M3의 상품군·브랜드별 학습/평가 분할, 제품 패밀리 연결, 모델 학습, S1 전략 생성, 2026년 신규 데이터 검증은 수행하지 않습니다.
- **가격의 한계:** 단위가격은 계산 가능한 제품에만 제공하며, 이를 프리미엄 등급 또는 최적 가격의 정답으로 간주하지 않습니다.
- **공개 저장소 유의:** 리뷰 원문과 격리 데이터에는 피부·건강 관련 진술과 작성자 식별자가 포함될 수 있습니다. 전처리 결과를 공개하기 전에 데이터 재배포 조건과 개인정보를 점검하세요. `.gitignore`는 실수로 출력 폴더를 커밋하지 않도록 돕습니다.

## 7. 자동 테스트 방법

```powershell
python -m unittest discover -s tests -v
```

**가상 데이터 테스트 4개를 포함**했습니다. 이는 실제 GitHub CSV 전체를 검사한 결과가 아닙니다. 테스트가 통과하면 로딩·용량 환산·손상 복원·격리·중복 처리 및 이전 버전에서 발견된 문제의 재발 여부 등 기본 기능을 확인할 수 있습니다.

## 9. 영어 표기의 사용 기준

- **주석·설명·안내 문구:** 한국어로 작성합니다.
- **Python 구문·함수 이름·CSV 열 이름·JSON 항목 키·명령 옵션:** 기존 코드 및 데이터와 연결되는 식별자이므로 원래 영어를 유지합니다. 이를 한글로 변경하면 다른 코드나 데이터와의 호환성이 깨질 수 있습니다.
- **학습용(`train`), 검증용(`validation`), 시험용(`test`):** 각각 모델 학습, 모델 선택·조정, 최종 내부 성능 측정을 위한 데이터 구분입니다.
- **격리(`quarantine`):** 불량 데이터를 즉시 삭제하지 않고 따로 저장하는 작업입니다.
- **임시 처리본(`staging`):** 전처리 중간 단계에서만 사용하는 파일입니다. 완료 시 제거합니다.
- **데이터 누출(`leakage`):** 학습할 때 알면 안 되는 검증·시험 정보가 학습에 섞여 평가가 부풀려지는 현상입니다.
